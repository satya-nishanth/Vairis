2 · Razorpay Payment Request Cycle
sequenceDiagram actor User participant Browser participant NextJS as Next.js Server participant DB as PostgreSQL participant RZP as Razorpay participant Webhook as /api/razorpay/webhook participant Resend participant Shiprocket User->>Browser: Click "Place Order" Browser->>NextJS: POST /api/checkout NextJS->>DB: Atomic stock check alt Out of stock DB-->>NextJS: stock = 0 NextJS-->>Browser: 409 error — show out-of-stock else In stock NextJS->>DB: Create Order (PENDING), decrement stock NextJS->>RZP: Create Razorpay Order (amount, currency) RZP-->>NextJS: razorpay_order_id NextJS-->>Browser: Return order_id + key Browser->>RZP: Open Razorpay SDK modal User->>RZP: Pay (UPI / Card / EMI) alt Payment failed RZP-->>Browser: failure callback Browser->>NextJS: POST /api/checkout/cancel NextJS->>DB: Restore stock Browser-->>User: Show retry else Payment success RZP->>Webhook: POST payment.captured (HMAC signed) Webhook->>Webhook: Verify Razorpay signature Webhook->>DB: Order → PAYMENT_CONFIRMED, clear cart Webhook->>Resend: Send order confirmation email Webhook->>Shiprocket: Book shipment (POST /orders/create) Shiprocket-->>Webhook: shiprocket_order_id + AWB Webhook->>DB: Save shipment record Webhook-->>RZP: 200 OK Browser->>Browser: Redirect → /order/confirmation/[id] end end
3 · Shiprocket Fulfillment + Tracking Cycle
sequenceDiagram participant Webhook as /api/razorpay/webhook participant NextJS as Next.js Server participant DB as PostgreSQL participant SHIP as Shiprocket API participant Courier as Physical Courier participant ShipWH as /api/courier/webhook participant Resend actor Customer Note over Webhook,SHIP: Triggered immediately after payment confirmed Webhook->>SHIP: POST /orders/create\n(items, address, SKUs, weight) SHIP-->>Webhook: order_id + AWB code + courier name Webhook->>DB: Save Shipment (awbCode, courierName, shiprocketId) DB-->>Webhook: OK NextJS->>DB: Order status → PROCESSING Note over SHIP,Courier: Shiprocket assigns courier, pickup scheduled Courier->>Courier: Pickup → In Transit → Out for Delivery loop Tracking updates SHIP->>ShipWH: POST tracking webhook\n(AWB, status, timestamp) ShipWH->>DB: Update Shipment.status alt Status = SHIPPED ShipWH->>DB: Order → SHIPPED ShipWH->>Resend: Send "Your order is on the way" email else Status = DELIVERED ShipWH->>DB: Order → DELIVERED ShipWH->>Resend: Send delivery confirmation email end end Customer->>NextJS: GET /order/track/[id] NextJS->>DB: Fetch Shipment (status, AWB, trackingUrl) NextJS-->>Customer: Show tracking status + courier link

⚠ Gaps Found in Current Spec

  • MISSING
    Shipping update emails — spec mentions order confirm email but not "shipped" or "delivered" emails. Shiprocket webhooks trigger these — need to add to spec.
  • MISSING
    EMI display on product page — Anil explicitly asked for EMI info on product detail pages. Not in spec. Razorpay provides affordability widget for this.
  • MISSING
    /api/cron/release-stock not in route tree — Section 5 page routes omits this endpoint. Minor but should be there.
  • MISSING
    SEO basics — Next.js chosen for SEO but spec doesn't mention sitemap.xml, robots.txt, or OG tags. Should be specified.
  • DECIDE
    Order cancellation — can customers cancel? Only before PROCESSING? What triggers stock restore + refund? No flow defined.
  • DECIDE
    Refund flow — PaymentStatus has REFUNDED but the process isn't described. Manual via Razorpay dashboard? Or automated?
  • DECIDE
    Direct payment links — Anil asked if Razorpay can generate shareable payment links (custom amount). In scope or not?
  • MINOR
    Mobile responsiveness — mentioned in team chat as requirement, not in spec. Should be stated explicitly.
  • MINOR
    Product image count — how many images per product? Any ordering/primary image? Not specified.
