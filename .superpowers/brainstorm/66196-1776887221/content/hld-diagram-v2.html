Migration path: swap DATABASE_URL → Azure PostgreSQL (Prisma). Auth → NextAuth.js (~4 hrs). Storage → Azure Blob (~2 hrs). Hosting → Azure Container Apps (Dockerfile). Cron → Azure Functions timer (no code change).

2 · Razorpay Checkout Payment Cycle
sequenceDiagram actor User participant Browser participant NextJS as Next.js Server participant DB as PostgreSQL participant RZP as Razorpay participant Webhook as /api/razorpay/webhook participant Resend participant Shiprocket User->>Browser: Click "Place Order" Browser->>NextJS: POST /api/checkout NextJS->>DB: Atomic stock check alt Out of stock DB-->>NextJS: stock = 0 NextJS-->>Browser: 409 — show out-of-stock item else In stock NextJS->>DB: Create Order (PENDING), decrement stock NextJS->>RZP: Create Razorpay Order RZP-->>NextJS: razorpay_order_id NextJS-->>Browser: order_id + key Browser->>RZP: Open Razorpay SDK modal (UPI / Card / EMI) User->>RZP: Pays alt Payment failed RZP-->>Browser: failure callback Browser->>NextJS: POST /api/checkout/cancel NextJS->>DB: Restore stock Browser-->>User: Show retry else Payment success RZP->>Webhook: POST payment.captured (HMAC signed) Webhook->>Webhook: Verify Razorpay signature Webhook->>DB: Order → PAYMENT_CONFIRMED, clear cart Webhook->>Resend: Order confirmation email Webhook->>Shiprocket: Book shipment Shiprocket-->>Webhook: AWB + shiprocket_id Webhook->>DB: Save Shipment record Webhook-->>RZP: 200 OK Browser->>Browser: Redirect → /order/confirmation/[id] end end
3 · Shiprocket Fulfillment + Tracking Cycle
sequenceDiagram participant Webhook as /api/razorpay/webhook participant NextJS as Next.js participant DB as PostgreSQL participant SHIP as Shiprocket API participant Courier as Physical Courier participant ShipWH as /api/courier/webhook participant Resend actor Customer Webhook->>SHIP: POST /orders/create (items, address, SKUs) SHIP-->>Webhook: order_id + AWB + courier name Webhook->>DB: Save Shipment, Order → PROCESSING Courier->>Courier: Pickup → Transit → Out for Delivery loop Tracking updates from Shiprocket SHIP->>ShipWH: POST tracking webhook (AWB, status) ShipWH->>DB: Update Shipment.status alt SHIPPED ShipWH->>DB: Order → SHIPPED ShipWH->>Resend: "Your order is on the way" + AWB + tracking link else DELIVERED ShipWH->>DB: Order → DELIVERED ShipWH->>Resend: Delivery confirmation + jewellery care guide end end Customer->>NextJS: GET /order/track/[id] NextJS->>DB: Fetch Shipment (status, AWB, trackingUrl, courier) NextJS-->>Customer: Tracking status + courier link
4 · WhatsApp Bot Request Cycle
sequenceDiagram actor Customer as WhatsApp Customer participant META as Meta Cloud API participant WAHOOK as /api/whatsapp/webhook participant INT as /api/internal/* participant DB as PostgreSQL participant AZAI as Azure OpenAI Customer->>META: "Show me gold rings under 15000" META->>WAHOOK: POST webhook (message + sender) WAHOOK->>WAHOOK: Verify Meta signature (X-Hub-Signature-256) alt product_search intent WAHOOK->>INT: GET /products?category=rings&maxPrice=15000&metal=GOLD_18K INT->>DB: Query products + variants + stock DB-->>INT: Matching products INT-->>WAHOOK: Product list WAHOOK->>AZAI: Format as natural reply (name, price, image URL) AZAI-->>WAHOOK: Human-friendly message else order_status intent WAHOOK->>INT: GET /orders/[id] INT->>DB: Order + Shipment DB-->>INT: Status + tracking URL INT-->>WAHOOK: Status response else general_query intent WAHOOK->>AZAI: Message + Vairis brand context prompt AZAI-->>WAHOOK: Smart reply end WAHOOK->>META: POST /messages (reply) META-->>Customer: WhatsApp message delivered
5 · Order Cancellation + Refund Cycle NEW
sequenceDiagram actor Customer participant Browser participant NextJS as /api/orders/[id]/cancel participant DB as PostgreSQL participant RZP as Razorpay Refund API participant Resend Customer->>Browser: Click "Cancel Order" on /account/orders/[id] Browser->>NextJS: POST /api/orders/[id]/cancel NextJS->>DB: Fetch Order (status, items, payment) alt Order is SHIPPED or DELIVERED NextJS-->>Browser: 400 — Cannot cancel, already shipped Browser-->>Customer: Show error message else Order is PENDING, PAYMENT_CONFIRMED, or PROCESSING NextJS->>DB: Restore stock (stock += qty for each OrderItem variant) alt Payment was captured (PAYMENT_CONFIRMED or PROCESSING) NextJS->>RZP: POST /v1/payments/{razorpayPaymentId}/refund\namount = full order total RZP-->>NextJS: refund_id + status NextJS->>DB: Payment.status → REFUNDED NextJS->>Resend: "Refund initiated — 5 to 7 business days" end NextJS->>DB: Order.status → CANCELLED NextJS-->>Browser: 200 OK Browser-->>Customer: Order cancelled confirmation end

Full refund only in MVP. No partial refunds. Razorpay processes bank transfer in 5–7 business days automatically — no manual intervention needed.

6 · Direct Payment Links Cycle NEW
sequenceDiagram actor Admin actor Customer as WhatsApp Customer participant AdminUI as /admin/orders/payment-link participant NextJS as Next.js Server participant DB as PostgreSQL participant RZP as Razorpay Payment Links API participant Webhook as /api/razorpay/webhook participant Resend Note over Admin,RZP: Admin generates link for bespoke/custom order Admin->>AdminUI: Enter customer name, mobile, amount, description AdminUI->>NextJS: POST /api/admin/payment-links NextJS->>RZP: POST /v1/payment_links\n(amount, customer details, description) RZP-->>NextJS: payment_link_id + short URL (rzp.io/l/xxx) NextJS->>DB: Save PaymentLink record (id, amount, customerId) NextJS-->>AdminUI: Short URL Admin->>Customer: Share URL via WhatsApp manually Note over Customer,Webhook: Customer pays via link Customer->>RZP: Opens link, pays (UPI / Card / EMI) RZP->>Webhook: POST payment_link.paid webhook (HMAC signed) Webhook->>Webhook: Verify signature Webhook->>DB: Create Order (PAYMENT_CONFIRMED)\nlink to PaymentLink record Webhook->>Resend: Send payment confirmation email to customer Webhook-->>RZP: 200 OK

No cart or checkout flow involved. Order is created directly in DB on webhook receipt. Useful for bespoke pieces, Instagram DM sales, or any off-site negotiation.
